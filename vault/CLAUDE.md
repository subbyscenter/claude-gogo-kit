# CLAUDE.md — 이 보관함(vault)의 운영 규칙

이 파일은 Claude가 이 Obsidian 보관함에서 일할 때 따르는 **규칙 원본(단 한 곳)** 이다.
목표: 세션이 끊겨도 업무 맥락·결정·노하우가 쌓이고 이어지는 **누적형 기억**을 만든다.

> Codex 등 다른 AI용 `AGENTS.md`는 이 파일을 가리키는 안내문일 뿐이다. 규칙은 여기에만 쓴다.

---

## 원전 (Karpathy 원문 — 수정하지 않음)

- [[LLM-WIKI]] — Karpathy의 "LLM Wiki" 설계 패턴. 이 보관함 구조의 근거. (원문은 일부러 추상적이며 "규칙은 네 일에 맞게 만들라"고 한다.)
- [[KARPATHY-CLAUDE]] — Karpathy 작업 원칙: ① 하기 전에 생각·가정 밝히기 ② 단순하게 ③ 필요한 곳만 고치기 ④ 확인할 수 있는 목표로 끝까지.

아래 규칙은 이 두 원문을 이 업무에 맞게 옮긴 것이다. 충돌하면 **원문 원칙이 먼저**다.

---

## 0. 설계 (Karpathy LLM Wiki)

1. **3층으로 나눈다**
   - `AI-Sessions/raw/` = 고치지 않는 원본 자료 (불변)
   - `AI-Sessions/wiki/` = Claude가 쓰고 관리하는 정리된 지식
   - 규칙 = 이 `CLAUDE.md`
2. **위키는 쌓이는 하나의 지식이다.** 매번 원본을 다시 읽어 답을 만들지 않고, 정리한 지식을 위키에 쌓아 다음 세션이 다시 쓴다.
3. **연결이 핵심이다.** 모든 wiki 문서는 관련 문서로 `[[위키링크]]`를 건다. 혼자 떨어진 메모는 자산이 아니다.
4. **관리는 Claude가 한다.** 상호 링크 갱신, 모순 표시, 일관성 점검처럼 사람이 미루는 일을 한 번에 여러 문서를 손봐서 없앤다.
5. **단순하게 시작한다.** 구조를 미리 크게 만들지 않는다. 같은 종류 문서가 3개 이상 쌓이면 그때 나눈다.

---

## 1. 기본 규칙

1. 일을 시작하기 전에 `index.md`, `log.md`, 관련 `AI-Sessions/wiki/` 문서를 먼저 본다.
2. `AI-Sessions/raw/` 원본은 **고치거나 지우지 않는다.**
3. 정리된 지식·결정·실수·프로젝트 문서는 `AI-Sessions/wiki/` 아래에 둔다.
4. 세션 인수인계 메모는 `AI-Sessions/conversations/`에 둔다.
5. wiki 문서를 새로 만들거나 크게 고치면 관련 문서로 `[[위키링크]]`를 걸고, `index.md`와 `log.md`를 갱신한다.
6. 사용자가 원하지 않는 한 비밀번호·인증값·고객 개인정보는 저장하지 않는다.

## 2. 명령 — 무엇을 읽고 무엇을 쓰는지 고정

### `save` — 지금 작업 내용을 위키에 남기기
- **언제**: "저장해줘", "옵시디언에 남겨줘"라고 할 때. 또는 다시 쓸 해결법·결정·실수·업무 규칙이 나왔을 때(자동 저장).
- **순서**: Save Filter(§4) → 통과한 것만 → 카테고리 정하기 → **모순 확인: 관련 문서와 내용이 부딪히면 옛 문서를 `status: superseded`로 내리고 Links에 새 문서를 적는다. 어느 쪽이 맞는지 모르면 양쪽에 `disputed: true`를 달고 보고** → 문서 형식(§7)으로 만들기/고치기 → 관련 문서 `[[링크]]` → `index.md`에 링크+한 줄 요약 → `log.md`에 한 줄.
- 필터를 하나도 못 넘으면 **저장하지 않고 이유를 말한다.**
- 자동 저장 뒤에는 **무엇을 어디에 저장했는지 한 줄 보고**한다 (사용자가 거절할 수 있게).
- 사용자가 "이거 특히 좋다 / 즐겨찾기"라고 하면 frontmatter에 `favorite: true`, `index.md`의 ⭐ 즐겨찾기에 올린다.

### `ingest` — raw 자료를 위키 지식으로
- **언제**: `AI-Sessions/raw/`에 새 자료(문서·회의록·기사·캡처 설명)를 넣고 "정리해줘"라고 할 때.
- **순서**: raw를 읽되 고치지 않음 → `wiki/sources/`에 요약 → 나오는 사람·거래처·조직은 `wiki/entities/` → 반복 개념은 `wiki/concepts/` → 결정은 `wiki/decisions/` → 서로 `[[링크]]` → `index.md`, `log.md`. (자료 하나가 여러 문서를 건드리는 게 정상.)

### `query` — 위키 기준으로 답하기
- **순서**: `index.md`로 위치 찾기 → 관련 문서 읽기 → **출처(문서 링크)와 함께** 답. 다시 쓸 가치가 있는 답이면 새 문서로 남기고 `index.md`/`log.md` 갱신.

### `reference` — 세션 시작 때 맥락 되살리기
- **언제**: "옵시디언 참조", "이어서 하자", `/gogo`.
- **순서**: `index.md` + 최근 `log.md` + `wiki/projects/`(특히 `pc-map`) + `wiki/decisions/` + 최근 `conversations/` → **지금 상태 / 핵심 결정 / 남은 일 / 다음에 먼저 볼 문서** 요약. 읽기만 한다.

### `lint` — 보관함 건강 점검
- 원본이 고쳐졌거나 wiki에 섞였는지 · `index.md`에 빠진 중요 문서 · 문서끼리 **모순** · 낡았는데 그대로인 내용(§7 신선도) · 아무도 링크 안 하는 **외톨이 문서** · **깨진 링크** · 저장하면 안 됐던 일회성 문서 · 개인정보.
- 점검 보고서(파일별 고칠 점)만 만든다. **사용자가 승인한 뒤에만** 고친다.

## 3. 자연어 → 명령

| 사용자 말 | 명령 |
| --- | --- |
| "저장해줘", "옵시디언에 남겨줘", "이거 위키에 적어줘" | `save` |
| "이 자료 정리해줘", "raw 읽고 위키로 만들어줘" | `ingest` |
| "위키에서 ~ 찾아줘", "~ 정리된 거 있어?" | `query` |
| "옵시디언 참조", "이전 맥락 불러와줘", "이어서 하자" | `reference` |
| "위키 점검해줘", "정리 상태 확인해줘" | `lint` |

세션을 "옵시디언 참조"(또는 `/gogo`)로 시작하고 "저장해줘"로 끝내면, 세션이 끊겨도 업무 맥락이 이어진다.

## 4. Save Filter — 저장해도 되는가

아래 5개 중 **하나라도** 맞아야 wiki에 저장한다.

1. 앞으로 일에서 **다시 쓸** 정보인가?
2. 다른 사람(또는 다음 세션)이 일을 **이어받으려면 꼭 읽어야** 하는가?
3. 결정의 **이유와 결정한 사람**을 나중에 찾아야 하는가?
4. **실패한 방법**이라 다시 하면 안 되는가?
5. 함께 지켜야 하는 **공통 규칙·양식**인가?

하나도 안 맞으면(일회성 답, 사소한 중간 생각, 확인 안 된 추측, 감상) 저장하지 않는다.

### 오염 막기
- `raw/`, `conversations/` = 낮은 신뢰 보관소 (원본·중간 생각·확인 안 된 메모).
- `wiki/` = 확인된 지식만. 올리려면 ① 필터 1개 이상 통과 ② 확인됐거나 출처가 있어야 한다.
- `decision` 문서는 **근거(`source`)와 결정한 사람(`owner`)** 이 없으면 올리지 않는다.

## 5. 카테고리

- `AI-Sessions/wiki/sources/` — raw 자료 요약·출처
- `AI-Sessions/wiki/entities/` — 사람·거래처·조직·제품처럼 반복해서 나오는 대상
- `AI-Sessions/wiki/concepts/` — 반복해서 쓰는 개념·용어·방법
- `AI-Sessions/wiki/decisions/` — 결정, 이유, 결정한 사람, 날짜
- `AI-Sessions/wiki/errors/` — 실패한 방법, 다시 하면 안 되는 실수
- `AI-Sessions/wiki/projects/` — 업무·프로젝트별 진행 상황 + `pc-map`(PC·폴더 지도)
- `AI-Sessions/wiki/guides/` — 사람이 쓰고 Claude가 따르는 가이드 (말투·양식·검토 기준 등)

필요해지면(같은 종류 3개 이상) 카테고리를 새로 만들고 여기에 한 줄 더한다.

---

## 6. 사람이 쓰는 가이드

`AI-Sessions/wiki/guides/`는 **사람이 채우고 Claude가 따른다.** 문서 양식, 보고서 말투, 거래처별 주의점 같은 판단 기준을 한국어로 둔다.
Claude는 작성·검토 일을 할 때 관련 가이드를 **먼저** 본다. 가이드가 바뀌면 `log.md`에 적는다.

---

## 7. 문서 형식

```markdown
---
type: source | entity | concept | decision | error | project | guide | handoff
date: YYYY-MM-DD
status: draft | active | superseded
owner: 선택         # 담당자·결정한 사람
source: 선택        # 근거가 된 raw 파일이나 외부 출처
favorite: 선택      # true = 핵심 자산 (index.md ⭐)
verifiedAt: 선택    # 마지막으로 사실을 확인한 날 (가격·규정처럼 낡는 정보)
disputed: 선택      # true = 다른 문서와 모순, 아직 결론 X
---

# 제목

## 요약

## 배경

## 내용

## 링크
- [[관련 문서]]
```

`status`: `draft`(작성 중) → `active`(유효) → `superseded`(대체됨). 대체된 문서는 지우지 말고 무엇으로 바뀌었는지 링크를 남긴다.
신선도: `verifiedAt`(없으면 `date`)이 90일을 넘긴 `active` 문서는 낡았을 수 있다 — `lint`가 보고하고, 답에 인용할 때 한 줄 경고를 붙인다.
