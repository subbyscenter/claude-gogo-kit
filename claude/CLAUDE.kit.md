# 이 PC 규칙 — {{PC_NAME}}

위 원문(Karpathy 가이드라인)은 그대로 따르고, 아래는 이 PC에 맞춘 규칙이다. 충돌하면 원문 원칙이 먼저다.

## 0. 말투·표기 (반드시)

- 사용자에게 보이는 모든 글(답, 중간 보고, 표, 질문)은 **항상 한국어**로 쓴다. 코드·커밋 메시지만 영어 허용.
- 사용자는 개발자가 아니다. 전문용어 대신 쉬운 말로, **무엇을 했고 사용자가 다음에 무엇을 하면 되는지**를 쓴다.
- '없음'은 숫자 0 대신 **X**, '있음'은 **O** (예: "오류 X"). 0과 O가 헷갈리지 않게.
- caveman(토큰 절약)은 기본으로 켜져 있다. 단 중요한 설명·경고·되돌리기 어려운 확인·여러 단계 안내는 줄이지 말고 또박또박 쓴다.

## 1. 세션 시작 = `/gogo`

- 사용자가 `/gogo`(또는 "고고", "점검하고 시작")라고 하면 gogo 스킬대로 점검 → 고치기 → 옵시디언 맥락 불러오기 → 시작.
- 점검만 따로: `{{GOGO}} check --fix`

## 2. 옵시디언 = 누적 기억 (Karpathy LLM Wiki)

- 보관함(vault): `{{VAULT}}` — 운영 규칙 원본은 `{{VAULT}}/CLAUDE.md`. 보관함 일을 할 때 먼저 읽는다.
- 원문 두 개(수정 금지): `LLM-WIKI.md`(설계 근거), `KARPATHY-CLAUDE.md`(작업 원칙).
- 사용자가 이렇게 말하면 → 명령:

| 사용자 말 | 명령 |
| --- | --- |
| "옵시디언 참조", "이전 맥락 불러와줘", "이어서 하자" | `reference` (index.md·log.md·projects 읽고 현재 상태 요약) |
| "저장해줘", "옵시디언에 남겨줘" | `save` |
| "이 자료 정리해줘" (raw에 넣은 자료) | `ingest` |
| "위키에서 ~ 찾아줘", "~ 정리된 거 있어?" | `query` |
| "위키 점검해줘" | `lint` |

- **자동 저장**: 다시 쓸 해결법·결정·하면 안 되는 실수·업무 규칙이 나오면, 말 안 해도 Save Filter(보관함 CLAUDE.md §5)를 통과한 것만 저장하고 "어디에 무엇을 저장했는지" 한 줄로 보고한다. 일회성 잡담·추측은 저장 X.
- **PC·폴더 지도**: 처음 보는 작업 폴더·프로젝트에서 일하게 되면 `AI-Sessions/wiki/projects/pc-map.md`에 한 줄(폴더 · 무엇 · 메모)을 더하고, 계속할 일이면 `wiki/projects/<이름>.md`를 만든다. 다음 세션은 이 지도로 폴더를 이해한다.
- 비밀번호·인증값·고객 개인정보는 보관함에 저장 X.

## 3. 디스코드 (사용자 답·결과물·알림)

명령 = `{{ASK}}` (아래에서 `ask`). 세션 이름 `--from` = 작업 폴더 이름이나 지금 하는 일 한 줄.

- **사용자만 정할 수 있는 결정**(답이 없으면 막히는 것)은 채팅에만 묻지 말고 디스코드 버튼 질문으로도 올린다. 질문 하나에 결정 하나, 추천안을 첫 선택지로:
  `ask post --from "<세션 이름>" --title "질문 한 줄" --text "설명" --options "추천안|다른 안" --recommend 0`
  올린 뒤 `ask next --from "<세션 이름>"` 을 **run_in_background** 로 켜 두면, 사용자가 버튼·반응·직접 쓰기로 답하는 즉시 세션이 깨어난다 (답을 받으면 다시 켠다).
- **결과물**(그림·문서·영상)을 보여 줄 때: `ask show --from "<세션 이름>" --title "무엇" --text "봐 주실 곳: ...\n궁금한 점: ..." --files <전체 경로>` → #결과물-피드백. 피드백은 같은 `ask next` 로 `FEEDBACK ...` 줄로 온다.
- **알림**: 오래 걸린 작업이 끝남·실패·사용자 확인이 필요할 때 `ask notify "내용"` → #알림. 사소한 진행 보고로 도배하지 않는다.
- **업무별 정리**: 일이 특정 업무에 속하면 `--topic <업무 이름>` → 봇이 그 업무 카테고리와 채널을 자동으로 만든다.
- **채널 늘리기·정리 부탁**을 받으면: `ask channel list` 로 지금 모양을 보고 → `channel create / rename / move --to / describe / archive`. 정리는 지우지 않고 `archive`(「보관함」 카테고리로 옮김). 진짜 삭제(`channel delete --yes`)는 사용자가 "삭제"라고 분명히 말했을 때만, 한 번 더 확인하고.
- 새 세션을 열면 `ask answers --from "<세션 이름>"` 으로 못 받은 답을 먼저 확인한다.
- 질문·알림에 비밀번호·키·개인정보를 쓰지 않는다. 봇이 꺼져 있다는 경고가 나오면 `{{GOGO}} bot start`.

## 4. 바로가기 창 · 오늘의 퀘스트 · 일정 (Ctrl+Shift+F)

사용자가 **Ctrl+Shift+F**를 누르면 바로가기 아이콘 창이 뜨고, 화면 오른쪽 위에 오늘의 퀘스트, 위쪽 가운데에 달력이 같이 뜬다. 세 가지 다 파일 하나씩이고, 사용자가 부탁하면 Claude가 그 파일을 고친다 (창은 다음에 열 때 바로 반영).

| 사용자 말 | 고칠 파일 | 형식 |
| --- | --- | --- |
| "바로가기에 ○○ 넣어줘", "바로가기 정리해줘" | `{{DESK}}/shortcuts.txt` | `[카테고리]` 줄 아래 `이름 \| 주소` (주소 = https 주소 또는 `C:\...` 폴더·파일). 위쪽 `#` 설명 줄은 그대로 둔다 |
| "퀘스트에 ○○ 추가해줘", "매일 할 일에 ○○" | `{{VAULT}}/내 일정/오늘의 퀘스트.md` | `## 분류` 아래 `- [ ] 할 일` · 하루 여러 번 `- [ ] 할 일 (0/3)` · 버튼 `- [ ] 할 일 → 이름=주소` (또는 `→ 바로가기 이름`) |
| "○월 ○일에 ○○ 일정 넣어줘", "일정 끝났어" | `{{VAULT}}/내 일정/일정.md` | `- [ ] 2026-12-03 \| 분류 \| 내용` · 시간 `- [ ] 2026-12-03 15:00 \| 약속 \| 치과` · 기간 `2026-12-10~12-12` · 끝남 = `[x]` |

- 날짜는 꼭 `YYYY-MM-DD`로 쓰고, "다음 주 화요일" 같은 말은 오늘 날짜로 계산해서 적은 뒤 "12월 3일(수)로 넣었어요"처럼 확인해 준다.
- 퀘스트 노트 맨 아래 `<!-- gogo-quest-date: … -->` 줄은 창이 매일 체크를 푸는 표시라 지우거나 고치지 않는다. 체크는 사용자가 창에서 누르니 Claude는 목록만 고친다.
- 고친 뒤 한 줄로 "무엇을 어디에 넣었는지" 보고한다. 창이 안 뜨면 `{{GOGO}} check --fix`.
- **로컬 서버(대시보드 등 `http://localhost:포트`)를 만들면** 상주시키지 말고 바로가기 창에 등록한다 — 꺼져 있을 때 바로가기를 누르면 창 없이 켜지고, 창 왼쪽 위 「서버 N개」에서 오래 안 쓴 것을 끌 수 있다:
  `node "{{KIT}}/desktop/servers.mjs" add --data "{{DESK}}" --port 8123 --name "이름" --cwd "<폴더>" --cmd "node server.mjs"` + 바로가기 한 줄(`이름 | http://localhost:8123/`).
  확인 = `node "{{KIT}}/desktop/servers.mjs" show --data "{{DESK}}"`. 서버는 `0.0.0.0`이 아니라 `127.0.0.1`에서 듣게 만든다 (회사 PC 밖으로 안 보이게).

## 5. 안전

- 이 키트는 이 PC 안에서만 일한다. 다른 PC·서버를 조작하는 기능은 없다.
- 회사 파일 삭제, 밖으로 보내기(메일·업로드·공유), 되돌리기 어려운 일은 먼저 묻는다.
